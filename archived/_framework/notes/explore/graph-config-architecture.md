# 图即配置（Graph-as-Configuration）架构模式

> 区域: 本地 explore（研讨区）
> 创建: 2026-09-09
> 状态: 🧪 本地探索 — 用户审阅后推送上游 code-craft-frame
> 来源: kotocord 节点编辑器重构全程实践（M0-M5，2026-09，[[node-editor-refactor-plan]]）

## 1. 问题

桌面工具类应用的管线（采集→处理→输出）最初总是硬编码在 main/controller 里。功能一多（kotocord: 字幕/情绪/TTS/提醒/未来的 OSC），硬编码连线的组合爆炸且用户无法自定义。引入"图形节点编辑器"时最大的架构陷阱是：**让图变成运行时**——数据每帧穿过图结构，实时性能和稳定性被 UI 技术栈绑架。

## 2. 模式：图即配置

**节点图只是管线的可视化描述（配置面），编译/实例化为既有 C++ 管线后运行；数据流永远在原生代码（Qt 信号槽）里，图不参与运行时。**

五个核心组件（kotocord 对应 `src/core/graph/`）：

| 组件 | 职责 | 关键约束 |
|---|---|---|
| **GraphModel** | 节点/边/参数的纯数据 + JSON 序列化 | 不依赖 UI；这是可移植资产，换前端只动视图层 |
| **NodeRegistry** | 节点元信息（端口名/数据类型）+ 实例工厂 + **连接器闭包** | 连接器在注册处捕获信号/槽成员指针（那里静态类型已知），编译器只做字符串/索引查找 |
| **GraphCompiler** | 校验（DAG/端口存在/类型匹配/连接器）+ 装配 | **先完整校验后装配**，失败不产生半装配状态 |
| **Pipeline** | 实例所有权 + 连接集合 | 拆除时先断连再**逆序销毁**（汇先于源）；为"候选编译成功再换入"提供移动语义 |
| **NodeCatalog** | 真实模块 → 节点类型的注册中心 | 与编辑器注册表分离（见 §3） |

## 3. 编辑器集成：幻影节点 + 桥接层

编辑器（QtNodes 等）里的节点是**幻影**——只描述端口/名称/类型，不实例化运行时模块。一个泛型委托模型 + 元数据描述即可适配全部节点类型，不必为每种节点写编辑器类。

桥接层（kotocord `GraphQtBridge`）负责：
- 正向：GraphModel → 编辑器模型（id 重映射、自动排布）
- 反向：编辑器模型 → GraphModel（Out 侧枚举连接防重复）

好处：编辑器库可整体替换（kotocord 线头 T7），升级/换库不动图核心。

## 4. 停机重建（保守的应用语义）

图变更不热插拔。Apply 按钮 = "应用到运行时"：
1. 导出编辑图 → 校验 → **候选 Pipeline** 编译
2. 成功才 `pipeline = std::move(candidate)` 整体换入（旧实例销毁，Qt 连接自动断开）
3. 失败只报错误清单，运行时原封不动
4. UI 侧重挂（rewire）：按**类型扫描**实例表（勿按固定节点 id——换模板即错位）；window↔实例连线收进 glue 集合先断后连；UI 槽一律读成员指针而非捕获旧实例指针

热插拔（运行中增量重建）作为线头，待停机重建成为实际痛点再启动。

## 5. 行为等价性：重构期的硬约束

把硬编码连线改造成图边时，**逐条对照旧行为**，不等价的加专用设施：

- 案例：TTS 若直接挂在渲染信号上，ASR 中间半截话也会被播报。旧代码只在 LLM 处理完的帧调用 synthesize → 为此给 controller 增加**专用信号**（ttsReadyForSpeech），只在旧调用点发射
- 等价性要变成**测试断言**（"渲染≥2 次、播报恰好 1 次"），不是口头承诺
- 非数据流连线（系统监控→UI 看板）保留直连并注明"旁路"，不硬塞进图

## 6. 复合节点：保守起步的粒度策略

三层粗粒度（源/处理/汇）起步，内部结构复杂的模块做成**复合节点**（语音输入=mic+双 ASR 引擎；编排器=队列状态机+LLM+颜文字），内部连线不暴露为子图。收益：
- 图的语义面（用户可编辑的东西）保持小而稳定
- 复合节点内部可以继续演化，不破坏图格式
- "展开为子图"作为线头，需要细粒度编排时再做

## 7. 适用判断

适用：管线型工具、输出组合多样（六条工作流 = 六张图而非六套代码）、实时性在原生层。
不适用：图本身就是产品（节点式创作工具，如 ComfyUI——那类需要图即运行时）、单一流水线且不会变的工具（过度设计）。
