# Practice 项目骨架

> 类型: `practice`
> 定位: 轻量级每日刷题练习
> 适用: LeetCode、OD 机试、算法竞赛等单文件练习场景

---

## 设计理念

Practice 是本框架最轻量的项目类型。与 reference（深度阅读）、reconstruction（轮次重构）、product（产品产出）不同，practice 面向**高频、轻量、单文件**的日常刷题场景：

- **一个题目 = 一个代码文件 + 一个笔记文件**
- 代码文件三位一体：答案 + 多解法 + 测试用例
- 笔记文件聚焦于思路探讨，不追求轮次式的完整记录
- 以题号作为文件和目录的命名基础

## 目录结构

```
<practice-dir>/                    ← 练习目录（如 LeetCodePractice/）
├── <题号>.cpp                      ← ★ 答案 + 多解法 + 简单测试用例
├── <题号>.md                       ← 思路探讨笔记
├── <题号>.cpp                      ← 下一题...
├── <题号>.md
└── ...
```

**扁平结构**：所有题目文件直接放在练习目录下，不嵌套子目录。题号前缀已足够区分和组织。

## 代码文件规范 (<题号>.cpp)

每个 `.cpp` 文件包含三个逻辑块：

```
┌─────────────────────────────────┐
│ 1. 问题描述（顶部注释块）         │
│    - 题号、题名、难度、标签       │
│    - 一句话描述                   │
├─────────────────────────────────┤
│ 2. 多解法类                      │
│    - Solution  (解法一)          │
│    - Solution2 (解法二)          │
│    - ...                        │
│    - 每个类标注: 思路 + 复杂度    │
├─────────────────────────────────┤
│ 3. main() 测试用例               │
│    - 基本 case                   │
│    - 边界 case                   │
│    - 验证输出与预期一致            │
└─────────────────────────────────┘
```

### 代码文件模板

```cpp
/*
 * LeetCode <题号>: <题名>
 * 难度: <Easy / Medium / Hard>
 * 标签: <tag1>, <tag2>, ...
 *
 * 问题描述:
 * <一句话描述>
 */

#include <必要的头文件>
using namespace std;

// ============================================================
// 解法一: <方法名>
// 思路: <一句话思路>
// 时间复杂度: O(...)
// 空间复杂度: O(...)
// ============================================================
class Solution {
public:
    // ...
};

// ============================================================
// 解法二: <方法名>
// 思路: <一句话思路>
// 时间复杂度: O(...)
// 空间复杂度: O(...)
// ============================================================
class Solution2 {
public:
    // ...
};

// ============================================================
// 测试用例
// ============================================================
int main() {
    Solution sol;

    // Test case 1 — 基本场景
    {
        // input → expected output
        // assert / cout 对比
    }

    // Test case 2 — 边界场景
    {
        // ...
    }

    cout << "All tests passed!" << endl;
    return 0;
}
```

### 代码规范要点

1. **解法编号**: `Solution`、`Solution2`、`Solution3`...（编号从 2 开始，基类不加编号）
2. **注释语言**: 推荐中文，便于快速回忆
3. **解法之间用分隔线**: `// ====...====` 清晰分界
4. **复杂度标注**: 每个解法必须标注时间和空间复杂度
5. **测试用例**: 至少覆盖 1 个基本 case + 1 个边界/特殊 case
6. **自包含**: 不依赖其他项目文件（如需要 `TreeNode` 结构体，在文件内定义）

## 笔记文件规范 (<题号>.md)

每个 `.md` 笔记文件对应一个题目，聚焦于**思路探讨**而非完整记录：

### 笔记模板

参见 `_framework/templates/practice-note.md`

### 笔记内容要点

1. **题目信息和标签** — 快速了解题目背景
2. **核心思路** — 用一句话讲清楚解题的关键洞察
3. **解法对比表** — 各解法的复杂度、优劣一览
4. **关键收获** — 这道题学到了什么
5. **踩坑记录** — 实际编码中的错误和修正
6. **相关题目** — 关联到其他类似题目

## 与其他项目类型的区别

| 维度 | practice | reconstruction | reference |
|------|----------|---------------|-----------|
| 粒度 | 单题 | 项目级 | 项目级 |
| 文件组织 | 扁平，题号命名 | curriculum/ 轮次 | notes/ 分析 |
| 代码结构 | 单文件多类 | src/ 多文件 | 源码不动 |
| 笔记深度 | 思路探讨 | 轮次笔记+QA | 架构分析 |
| 测试 | 内嵌 main() | 实验独立 src/ | 按需运行 |
| 简历产出 | 无 | 有 | 无 |
| 适用场景 | 每日刷题 | 系统学习项目 | 阅读开源项目 |

## 从现有扁平目录迁移

如果一个练习目录已经是平铺的 `.cpp` 文件（如当前的 LeetCodePractice），迁移到本规范只需：

1. 为每个 `.cpp` 补充 `main()` 测试用例
2. 为每个 `.cpp` 创建对应的 `.md` 笔记
3. 统一注释格式（问题描述 + 复杂度标注）

迁移过程不需要移动文件或创建子目录。
