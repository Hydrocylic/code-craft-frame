## 1. 为什么需要这份约定

## 2. 转交用 prompt（**整段复制给下游工作区的 agent**）

```text
【来自 <本工作区> 的对接请求】你在 <下游工作区路径> 工作区工作。<本工作区>（<一句话定位>）要按你们的
框架产出 <产物形态>，但两个工作区互不访问（信息隐私边界），信息只通过人类转交。
请你只提供规则与结构——不要提供仓库内容本身，也不要包含任何个人信息。

请按下面 N 项逐条作答；不确定的写“未定”，不要猜：

1. <要什么：目录结构 / 命名 / schema / 资源 / 托管 / 红线 / 交付形态 / 样例>
2. …

输出格式：Markdown，按 1–N 编号；每条标注“确定 / 未定 / 由谁决定”。
末尾另写三条：① 你所在工作区的规则版本或日期；② 这份约定的适用范围与有效期；
③ 是否允许 <本工作区> 把这份约定存成带日期与来源的快照，供离线产出时遵循。

隐私边界（请遵守）：只返回规则、结构、schema 与脱敏样例；不要返回任何人的真实简历内容、联系方式、
账号凭据、私有数据，或仓库中未公开的第三方素材。
```

## 3. 回执怎么带回来

1. 用户把下游 agent 的答复**整段粘贴**回本仓；
2. 按 `handoff-conventions.md` 落盘到 `<handoff-dir>/spec/<YYYY-MM-DD>-<主题>.md`
   （头部登记来源 / 取得日期 / 提供者 / 核验状态 / 适用产物 / 有效期）；
3. 在 `<handoff-dir>/README.md` 的“对接状态”登记生效版本。
