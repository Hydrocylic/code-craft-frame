## 1. ID 约定

1. **ID = `<job>-<YYMMDD>`**：`job` 表功能（**不表轮次号**），日期用该对话的创建日。
   job 词表（可增补；多词用 CamelCase）：`framework` / `curriculum` / `code` / `debug` / `research` /
   `survey` / `ProductDesign` / `docs` / `test`。
2. **自指一律用 ID**。
3. **一个 ID = 一段对话 + 一个「服务对象」**（一个轮次 / 一个任务单元 / 一条常驻线）——服务对象是
   **生命周期管理的主键**。
4. **换服务对象 = 新 ID、新行，不写 `旧 → 新` 箭头**；交接写「接手自 `<旧ID>`（其服务对象 = `<旧轮次>`）」。
5. 同一服务对象内换对话 → 新 ID + 备注"续话，前一段 = `<旧ID>`"。
6. **归档以"服务对象结束"为单位**；常驻线按"对话结束"归档。
7. 新 Agent 开局先读本表并**自报 ID + 服务对象 + 写入范围**。

## 2. 生命状态

### 2.1 六态

`待启动 → 在岗 → 交接中 → 已归档`；旁路 `阻塞`（等用户 / 等外部）、`暂停`（临时叫停）；
台账里也常用 **`挂起（等后续任务）`**（暂时不推进，但不关闭对话）。

### 2.2 上下文档位（归档决策的输入）

| 档位 | 判据（见 agent-context-economy.md） |
|---|---|
| 宽松 | 对话新开、工具调用少 |
| 过半 | 工具调用 > 20 次，或用户感觉变慢，或已跨一个轮次 / 任务 |
| 吃紧 | 工具调用很多且跨两个以上轮次 —— 建议进入归档四步 |

### 2.3 归档四步

1. 判据命中（上下文吃紧 / 任务完成 / 线头转交）
2. 交接件落 `notes/handoffs/`（固定模板）
3. **冷启动测试**：接手方只读「交接件 + 执行日志 + 相关 spec」能否接着干
4. 台账收尾：行移入「已归档」+ 归档日 + 交接件指针 → 用户关闭对话

> **轻量归档**：产出全部是仓内可读文件的线可省交接件（备注写"交付物 = 仓内改动 + 执行日志条目"）。
