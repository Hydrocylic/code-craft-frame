# 协作框架总纲

版本：3.0 · 2026-10-19 · 本文件解释边界与原则；操作见[手册](MANUAL.md)，冷启动见[根入口](../AGENTS.md)。

本框架面向“持续开发 + 文档协作”的工作区：规则、任务、证据与产出分开保存，Agent 与人类按同一套路径与授权协作。学习、调研、求职等用法属于实例策略，不写进通用骨架。

## 一、设计哲学

1. **完成当前工作优先于维护框架**。小任务不强制套完整文件集；流程成本必须对应风险。
2. **一类事实一个正本**。入口与模板给指针，不复制出第二套权限、状态或数字。
3. **授权、所有权、证据分开**。有工具不等于获授权；有交接不等于有锁；跑过测试不等于当前树通过。
4. **可逆与可追溯**。保护未提交工作；结构调整先有清单；当前状态可更新，历史依据不被新结论覆盖。
5. **按需加载**。先完成最小闭环，遇到具体风险再读细则；不让每个 agent 阅读整套框架。

## 二、内容归属与参考骨架

目录名与分区是实例策略；下面只是可用的最小骨架，不是所有工作区的必建清单。

```text
<workspace-root>/
├── AGENTS.md              # 冷启动入口：阅读顺序 / 边界 / 指针
├── README.md              # 人类入口：当前状态与目录职责
├── _framework/            # 规则、模板、变更账
│   ├── FRAMEWORK.md
│   ├── MANUAL.md
│   ├── CHANGELOG.md
│   ├── notes/spec/        # 按需读取的现行规范
│   ├── templates/         # 结构参考，不是必建文件
│   └── private/           # 本地私有；不进 Git
├── <service-object>/      # 当前任务/记录；实例可改名或分区
├── proposals/             # 未决定的提案；不自动授权
├── archived/              # 退出前沿的材料；不维护内部链接
└── _local/<ID>/           # 工作区起点临时件/交接；不属任何 Git 仓
```

- 产品代码、参考克隆、重资产等是否与规则库同仓，由实例决定；不同仓时，规则库只留指针与授权边界。
- 不为工具短板建常驻区，不预建空目录。新增分区前说明它管理什么、现有区为什么不能承担、谁维护、何时退出。
- 历史材料退出当前视野后进 `archived/`；归档不要求重新验收或修历史链接，删除由所有者人工决定。
- 临时件统一放工作区起点的 `_local/<ID>/`，不放进任何 Git 仓；使用前记用途与清理条件。

## 三、授权、角色与所有权

角色词表、ID 的 job 名和具体路径属于实例策略；本框架只约定三条边界：

1. **一项授权有唯一契约**：任务的目标、可写/不可写路径、前置、可判定验收与验证执行者写在契约里；角色名不自动产生路径或命令权限。
2. **按路径单写**：同一文件或共享接口同一时间只有一个写者；重叠修改先停、重读、协调。登记不是锁。
3. **证据对应实际版本**：区分已读、已运行、采信记录与未验证；交付不等于验收通过。

默认由用户决定是否启动新的执行线；Agent 不自动派遣其他 Agent。对话结束与服务对象完成分开判断。

## 四、任务组织

任务是“一个服务对象 + 一个可验收闭环”，不是固定文件集。

- 契约优先并入服务对象的 plan/design；只有没有自然落点时才独立成件。
- 简单任务直接在当前正文写目标、范围、验收与结果；多步依赖、设计取舍、独立验收才建 plan。
- 执行时序、异常或验证过程需要长期保留时才建 log；代码品读有独立交付价值时才建 review。
- 不强制 plan / log / review 三件套同时存在；一个任务只有一个范围与验收正本。
- 跨对话接力按需写本地交接；正式结论先落产出，交接只引用，不建立第二正本。

## 五、交付与完成

完成须说明：改了什么、在哪个版本验证、实际结果、未验证面、剩余项与下一动作。

- 用户人工验收不被自动化读数替代；独立验证不冒充实现者自查。
- 会话归档、任务收尾、功能达标是三个不同状态。
- 常规内部取舍不记账；真实风险、权限缺口、共享写入冲突和失败不能隐去。
- 记录按“最小正文”：只写会改变下一动作的信息；长输出与原始轨迹留证据文件，按需取读。

## 六、规则的成熟与上下游

问题先记录在发生处；反复发生且能写成可执行动作才提升为规则。

- 本库是通用上游：只收可跨工作区复用的规则、方法与模板，不收产品路径、任务编号、个人或未公开内容。
- 实例先在自己的 `_framework/` 实践；成熟后由用户授权，泛化并提交到本库；本库不反向覆盖实例。
- 实例按 commit 选择性采纳本库；不自动 pull、不 submodule、不覆盖实例已有规则。
- 采纳与提升的流程与记录格式见[规则同步机制](notes/spec/rule-sync-mechanism.md)与[变更账](CHANGELOG.md)。

### 求同存异（最大公约数）

通用上游只取各实例实践中**跨工作区成立**的部分，不追求把所有项目的经验合并成一套。

| 层级 | 判据 | 落点 |
|---|---|---|
| **通用规则** | 去掉产品名、角色词表、具体路径后仍可执行；至少两个工作区适用 | 总纲、手册或 `notes/spec/` |
| **可选实践** | 有明确适用条件；默认不启用，实例按需采用 | 规范中的“可选实践”节 |
| **项目特色** | 只在单个项目成立，或依赖其产品/角色/工具 | 留在实例，不进入上游 |

实例可以保留自己的目录、角色、命令与偏离，不要求同版；偏离记录在实例 `UPSTREAM.md`。上游收“公约数”，不收“唯一正确答案”。

## 七、版本与记录

规则变更记 [CHANGELOG](CHANGELOG.md)：日期、类型、变更内容、来源、影响范围与验证。

| 事实 | 正本 |
|---|---|
| 当前规则与边界 | 本文件、[手册](MANUAL.md) 与 `notes/spec/` |
| 任务授权与验收 | 对应任务的 plan / design / contract |
| 当前工作状态 | 实例的 `README.md` 或任务入口 |
| 并行写者状态 | 用户或当次 kickoff/交接说明；非常驻正本 |
| 规则变更历史 | `CHANGELOG.md` |

同步不明时记录“不一致待核”，不选一个好看的状态宣称完成。

## 八、Git

Git 只读查询、写操作授权、检出与验证对应树，见 [Git 规范](notes/spec/git-practices.md)。本文件不重列命令。

## 九、框架自身

- `notes/spec/` 保存现行规范，按需读取，不要求通读。
- `templates/` 只提供结构；模板存在不代表必须生成文件。
- `archived/` 保存退出当前规范的材料；不作为当前授权依据。
- 新增规则前先查重复、修正正本或改善模板，而不是再添例外。
