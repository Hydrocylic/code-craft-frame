# 敏感信息检查与脱敏（spec）

> 区域: spec（规范区）
> 框架版本: v3.0
> 创建: 2026-10-19
> 来源: 公开上游与多工作区协作的长期脱敏需求；首次对上游库的扫描实践

## 目的与适用

公开或可能公开的仓库，在提交、提升到上游、发布或对外交付前，检查内容、历史与元数据中是否含敏感信息。适用于规则库、文档库、模板库，也适用于实例在对外交付前自查。

**长期口径**：脱敏不是一次性清理，而是每次对外写入前的检查项，加上周期性历史复核。自动扫描是辅助，不替代人工判断。

## 什么算敏感

| 类别 | 例子 | 默认处理 |
|---|---|---|
| **凭据** | token、API key、密码、私钥、`.env`、带用户名密码的 URL | 阻止提交；已提交则轮换并评估历史 |
| **个人数据** | 邮箱、电话、身份证号、住址、简历正文、账号凭据 | 去标识或移出公开区 |
| **内部信息** | 未公开产品名、客户名、任务编号、未发布计划、内部路径 | 泛化，或留在实例 |
| **机器信息** | 绝对路径、用户名、主机名、内网 IP | 改占位符 |
| **第三方** | 未公开素材、受限许可内容、他人私有数据 | 移出，或确认许可与授权 |

**项目名 / 任务号不一定是“秘密”**，但公开上游不默认收录；按[求同存异](../../FRAMEWORK.md)原则留在实例。已经公开的历史项目名，是否清理由所有者决定，不在本 spec 自动授权改写历史。

## 检查时点

- 提交前（至少是准备公开的内容）
- 提升到上游前
- 发布 / 对外交付前
- 周期性历史复核（建议每季度，或每次大整理 / 迁移后）
- 新增、移动或解档 `archived/` 等历史目录时

## 检查面

1. **工作树内容**：文本文件中的凭据、个人数据、内部标识、绝对路径。
2. **文件名**：`.env`、`.pem`、`.key`、`.pfx`、`id_rsa`、`secret`、`credential`、`token` 等。
3. **Git 历史**：已删除文件、旧版本中的凭据；只列文件，不回显内容。
4. **提交元数据**：作者 / 邮箱 / 远程 URL。作者邮箱通常已公开，评估即可，不默认视为阻断。
5. **二进制 / 大文件 / 压缩包 / 截图**：自动扫描不覆盖，需人工判断。
6. **示例、模板、归档**：具体项目名、内部任务号、真实路径、真实数据。

## 快速扫描（PowerShell）

本库脚本：`_framework/scripts/check-sensitive.ps1`。默认扫工作树；`-History` 加历史；`-Out` 写报告。脚本只报类别 / 文件 / 行号，不回显匹配值；凭据与 PII 作为失败项，绝对路径作为 review。它是辅助，不替代人工判断；脚本自身与本文因含模式字符串而默认排除。

以下命令可直接复制使用。只输出文件与行号，不回显匹配值。把 `<root>` 换成仓库根。

```powershell
$root = '<root>'
$secret = 'ghp_[A-Za-z0-9]{20,}|github_pat_[A-Za-z0-9_]{20,}|glpat-[A-Za-z0-9_-]{20,}|AKIA[0-9A-Z]{16}|AIza[0-9A-Za-z_-]{35}|-----BEGIN [A-Z ]*PRIVATE KEY-----|https?://[^/\s:]+:[^/\s@]+@'
$pii    = '[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}|\b1[3-9]\d{9}\b|\b\d{17}[\dXx]\b'
$path   = '[A-Za-z]:\\[^\s"''<>|]+|\\\\[^\\\s]+\\[^\\\s]+'

Get-ChildItem -LiteralPath $root -Recurse -File -Force |
  Where-Object { $_.FullName -notmatch '\\\.git\\' } |
  Select-String -Pattern $secret, $pii, $path -Encoding UTF8 |
  Select-Object Path, LineNumber
```

历史扫描（只列 `commit:path`）：

```powershell
$revs = git -C $root rev-list --all
git -C $root grep -l -I -E $secret $revs
```

提交元数据：

```powershell
git -C $root log --all --format='%an <%ae>' | Sort-Object -Unique
git -C $root remote -v
```

文件名：

```powershell
Get-ChildItem -LiteralPath $root -Recurse -File -Force |
  Where-Object { $_.Name -match '(?i)(\.env|\.pem$|\.key$|\.pfx$|\.p12$|id_rsa|secret|credential|token|password)' }
```

> 本 spec 自身含模式字符串；扫描时排除本文件，或把其中的模式当作文本示例，不当作命中证据。

## 发现后的处理

1. **未提交**：移除、改写或移到本地私有区；不要用 `git add -f` 绕过忽略。
2. **已提交未推送**：修正提交（`amend` / `rebase` 由用户执行）；不要静默覆盖他人工作。
3. **已推送**：评估暴露面；凭据立即轮换；个人数据按用户决定；历史重写是最后手段，需用户明确授权并通知协作者。
4. **记录**：在 `CHANGELOG` 或事件记录写“发现 — 处置 — 验证”，不复制敏感值本身。
5. **不静默**：不把“扫描通过”当成安全保证；不隐藏真实风险；不因怕误报而删除必要的说明。

## 边界（求同存异）

- 通用模式与流程进本 spec；实例可加自己的模式（客户名、内部域名、产品名、本机路径）。
- 不把某个项目的敏感词表强加给所有实例。
- 自动扫描不覆盖图片、二进制、语义泄露和上下文判断；高风险交付仍需人工复核。
- 不自动把仓库内容上传到外部服务或第三方扫描平台。
- 发现历史泄露时，先评估、再决定是否重写；不在本 spec 授权改写历史。

## 检查清单

- [ ] 工作树无凭据 / 私钥 / `.env`
- [ ] 无个人数据（或已去标识）
- [ ] 无未公开项目名 / 任务号 / 内部路径（或已确认可公开）
- [ ] 无绝对路径 / 用户名 / 主机名 / 内网 IP
- [ ] 文件名无敏感项
- [ ] 历史扫描无凭据；作者邮箱 / 项目名已评估
- [ ] 归档 / 示例 / 截图 / 二进制已人工复核
- [ ] 发现项已处置并记录
