# 模板规范

> 区域: spec（规范区）
> 框架版本: v3.0

---

## 模板设计原则

1. **语言无关** — 代码块使用 `<language>` 占位符，命令使用 `<run-command>` 占位符
2. **自文档** — 每个模板用 HTML 注释标注模板路径和适用位置
3. **占位符清晰** — 使用 `<描述>` 格式的占位符，便于查找替换
4. **注释指引** — 关键部分附带注释说明填写方式

## 长期读物、架构说明与设计意图

适用：长期阅读材料及其内容任务契约。按读者问题分流，不按“验证”“待核”等标题整段搬走。

### 内容归属

| 回答的问题 | 唯一正文位置与边界 |
|---|---|
| 当前软件怎样工作、模块如何协作、改变一处会影响什么 | 持久读物对应主题：实现解释、关键链路、接口、不变量、设计理由、技术限制和代码定位 |
| 功能为何存在、应该有什么行为 | 规格 / 需求区：经确认的目标、非目标和验收要求；读物解释实现并引用要求，不复制规格 |
| 未来准备如何修改、尚未实现的方案 | 活动任务的计划/设计；没有任务归属的未定方案放提案区。批准不等于已实现 |
| 本次谁做什么、进度、待裁与验收 | 任务的唯一计划或其指向的独立契约；不进入读物或索引 |
| 为什么相信某结论、如何复算检查 | 计划的短交付段；确有独立复核价值才拆证据件 |
| 项目自己的词、术语定义 | 术语表（产品/交互词或架构词）；只放词与紧定义，不放实现/规格 |
| 求职项目描述、面试问答 | 求职区（如实例需要）；不是产品读物；不写产品规格/任务状态 |
| 下一对话如何继续、保护什么未提交面 | 聊天或工作区起点 `_local/<ID>/` 的 kickoff/交接；不承载新增授权 |

位置只是归属，不是必建文件集。

### 正文写法与事实边界

1. **先解释再定位**：开头说明读者问题、范围和一行适用代码基线。按需要用具体动作讲清触发、数据归属、经过的模块、结果、失败边界与取舍；符号表用于核查，不以完整导出清单代替说明。
2. **区分四类陈述**：实现事实以对应基线的代码为依据；已确认意图引用现行要求或技术决定；解释性推断明确尚无原始决策依据；新建议回任务设计/提案。不能由“现在这样实现”推定“设计者为了……”或“以后必须如此”。
3. **保留必要技术限定**：静态导入图与运行时调用的区别、类型依赖的编译期耦合、接口适用条件等留在正文。脚本排障、未跑步骤和下一批安排归任务/证据。关键断言不确定时就地限定或暂不作为事实发布，不能只靠整篇“待核”遮盖。
4. **正文与证据分离但可追溯**：代码定位按文件＋符号，行号仅作带基准的快照；关键非显然结论可链接短证据，但读懂正文不应先读任务记录。**证据必须持久**——不要链任务目录中的证据（任务归档会断，属耦合缺陷）。
5. **索引服务阅读**：只导航已经存在的正文并说明其回答的问题；任务 ID、待产出表、派发/查收队列归计划。验收状态只在计划维护。

### 设计理由的存储与维护

普通理由和代价就近写在主题正文，不另建决策台账。满足 ADR 三判据（难逆转 + 无上下文会奇怪 + 真实权衡）且确需跨文档独立引用的已落实技术决定，才按需放独立 decisions 件：问题、选择、理由、代价与适用条件，不保存批准聊天和实施进度。尚未实现的已批准方案仍归任务设计；实现确认后由获授权内容线更新当前读物。

代码变化触及已描述的接口、职责、链路或理由时，在对应任务明确受影响主题与维护者；更新实际涉及的正文及基线，或具体标明不再适用的范围，不要求每次改动重算全仓。

### 读物任务的验收

- 读者不读任务/kickoff，也能说明一个职责、一条关键链路及其限制；涉及意图时能区分已确认理由与推断。
- 具体引用可定位，关键断言的范围与依据一致；检查可读性不替代事实核验。
- 任务状态、复核过程与接手信息有各自落点；同文件一个当前写者，索引维护与正文写入须串行。

## 模板元要求

每个模板文件必须包含：

1. **标题** — `# <模板用途>`
2. **注释头** — HTML 注释标注模板路径和适用位置
3. **节结构** — 清晰的 Markdown 节
4. **内联注释** — `<!-- 填写说明 -->` 格式的指引

## 占位符约定

| 占位符 | 含义 |
|--------|------|
| `<project-name>` | 项目名称 |
| `<name>` | 通用名称 |
| `<title>` | 标题（kebab-case 用于目录名，自由文本用于标题） |
| `<concept-name>` | 概念名称 |
| `<exp-name>` | 实验名称 |
| `<language>` | 编程语言标识 |
| `<run-command>` | 运行命令 |

## 数学公式书写规范

笔记中所有数学讨论**必须使用 LaTeX 语法**，不使用纯文本或 ASCII 艺术拼接。

**格式要求**：

| 场景 | 语法 | 示例 |
|------|------|------|
| 行内公式 | `$...$` | `$f(n) = f(n-1) + f(n-2)$` |
| 独立公式 | `$$...$$` | `$$f(n) = \sum_{i=1}^{m} a_i f(n-i)$$` |
| 矩阵 | `\begin{pmatrix}...\end{pmatrix}` | `$$\begin{pmatrix} 1 & 1 \\ 1 & 0 \end{pmatrix}$$` |
| 多行对齐 | `\begin{aligned}...\end{aligned}` | 推导步骤使用 `&` 对齐 |
| 上下标 | `_{}` `^{}` | `$M^{\,n-1}$`, `$a_{m}$` |
| 省略号 | `\cdots` `\vdots` `\ddots` | 按方向选用 |
| 求和/求积 | `\sum` `\prod` | `$\sum_{i=1}^{n}$` |

**禁止事项**：

- ❌ 禁止用纯文本代码块写矩阵或公式（如 `[1 1] [f(n-1)]`）
- ❌ 禁止用 ASCII 艺术画矩阵框线（如 `┌ ┐ │ └ ┘`）
- ❌ 禁止用 `^` 代替上标、`_` 代替下标而不加 `$` 包裹
- 允许：代码块包裹算法伪代码或程序逻辑（非数学公式）

**适用范围**：所有笔记文件均适用本规范。
