# 可调整内容

> 区域: explore（探讨区）
> 框架版本: v2.0
> 最后更新: 2026-08-07

---

## 说明

以下内容是框架中可以**根据具体场景调整**的部分。这些不是"错误"，而是框架设计的柔性边界——在某些场景下偏离标准做法是合理的。

---

## 目录结构层面

### 1. 引用源位置

**标准**: 参考源码放在 `reference/<name>/<source>/`

**可调整**: 如果参考源码过大（如完整克隆的 Linux 内核），可以：
- 在 `reference/<name>/` 中只放分析笔记，源码路径在 README.md 中说明
- 使用 git submodule 减少仓库体积
- 将源码放在仓库外的文件系统中，笔记中用绝对路径引用

### 2. envs/ 目录

**标准**: envs/ 放在仓库根目录

**可调整**: 如果所有项目使用同一环境且不需要版本管理：
- 可以完全省略 `envs/` 目录
- 环境配置可以放在 `notes/resources/` 中作为参考资料

### 3. notes/ 全局笔记

**标准**: notes/ 放在仓库根目录，包含 daily/、concepts/、resources/

**可调整**: 随着项目增多，concepts/ 中的概念笔记可能需要重新组织（如按领域分子目录）。这是在预期之内的，不影响框架规则。

## 项目类型层面

### 4. 项目可以跳过类型

并不是所有内容都需要归入三种类型之一：

- 临时探索的代码 → 直接放在 `experiments/` 下，不需要 meta.yaml
- 快速验证想法 → 创建轻量级的 notes 文件即可
- 外部工具的配置文件 → 放在 `envs/` 或项目 README 中说明

### 5. 项目类型的"灰色地带"

某些项目可能同时具备两种类型的特征：

- **分析+重构**: 一个 reference 项目中包含了少量的实现验证代码 → 要不要转为 reconstruction？如果实现量小且只是为了验证理解，保留在 reference 中即可
- **重构+产品**: 一个 reconstruction 项目的产出质量已经接近产品级 → 要不要转为 product？如果学习目标已达成，可以转换；如果还想继续学习，先不动

### 6. 参考项目元文件时机

**标准**: 创建参考项目时立即添加 `README.md` + `meta.yaml`

**可调整**: 初始阶段（刚引入 submodule、尚未开始分析）可以保持裸 submodule 状态，不强制补全元文件。理由：
- 初始时还没有足够信息填写 `meta.yaml` 中的描述、标签、代码规模等字段
- 过早填写会导致内容空洞或需要反复修改
- `README.md` 和 `meta.yaml` 可以在开始对该参考项目进行系统分析时再补充
- 裸 submodule 本身已经通过 `.gitmodules` 记录了来源 URL

**影响**: 框架 MANUAL.md §"创建参考项目"中步骤 3-4（复制 meta.yaml、创建 README.md）从"必须"降级为"按需——在开始分析时执行"。

### 7. 轮次粒度

**标准**: 每个轮次聚焦一个独立的知识点/实现模块

**可调整**: 轮次的粒度取决于：
- 学习者的背景知识（初学者需要更细的粒度）
- 参考项目的复杂度（大型项目需要更多轮次）
- 实验的独立程度（能独立跑的轮次通常更适合）

### 10. knowledge-base.md 的使用范围

**标准**: product 项目推荐使用 `docs/knowledge-base.md`（单体 QA 文件，不按主题拆分）进行基础知识积累。

**可调整**: reconstruction 项目的知识积累应通过轮次 QA（`curriculum/r<NN>-<title>/qa.md`）进行，每个轮次的知识就近记录，而非集中到一个全局 knowledge-base 文件。原因：
- reconstruction 以轮次为独立的课程单元，知识天然属于产生它的轮次
- 轮次 QA 的"未解决问题"机制已经提供了跨轮次的知识流转
- 集中式 knowledge-base 更适合 product 这种"持续建造"的场景，不太适合 reconstruction 的"阶段式学习"

如果一个 reconstruction 项目后期转为 product，可在转换时将各轮次 QA 中的知识点提炼合并到 knowledge-base.md。

## 模板层面

### 7. 模板不是必须完全填写

模板中的所有节都是建议，可以：
- 删除不适用的节
- 添加自定义的节
- 如果某个轮次不需要 Q&A，qa.md 可以很简短

### 8. meta.yaml 的额外字段

标准字段之外，可以自行添加：
- 个人评分（对自己学习质量的评估）
- 时间追踪（实际花费的小时数）
- 自定义状态（在 planned/in-progress/completed/archived 之外）

---

## 同步层面

### 9. 框架同步频率

**标准**: 每次 CHANGELOG 变更后检查所有项目的 meta.yaml

**可调整**: 当项目数量多时，可以：
- 只检查 active 状态的项目
- 批量更新（积累若干变更后一次性同步）
- 对 archived 项目跳过同步
